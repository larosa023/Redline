# Redline 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and ship Redline 1.0, a Windows GPU tuning + monitoring app (NVIDIA/AMD/Intel) with auto-tune, profiles, safety nets, themes, overlay and a built-in updater, as one release.

**Architecture:** A cross-platform core (`Redline.Core` domain + `Redline.Engine` orchestration) holds every rule and is unit-tested against a simulated GPU. Windows-only adapters (vendor SDKs, LibreHardwareMonitor, power plans, D3D11 stress test, PresentMon) plug into it. A `Redline.Helper` Windows service hosts the engine and is the only process that touches hardware; the WinUI 3 app talks to it over a named pipe.

**Tech Stack:** .NET 10, C# 13, xUnit, WinUI 3 (Windows App SDK 1.8), CommunityToolkit.Mvvm, LiveCharts2, H.NotifyIcon.WinUI, Vortice.Windows (D3D11/D2D), LibreHardwareMonitorLib, PresentMon (console, MIT), Velopack, GitHub Actions (windows-latest).

**Spec:** `docs/superpowers/specs/2026-11-23-redline-design.md`. Mockups: https://claude.ai/artifact/D2Ao6hMm1QG45KCdG7XEe5 (page "Round 2 — themes").

## Global Constraints

- Windows 10 21H2+ and Windows 11, x64 only. `net10.0` for Core/Engine/Ipc/ViewModels/tests; `net10.0-windows10.0.19041.0` for Windows projects.
- No bundled kernel drivers. Use only vendor DLLs already installed with the GPU driver (`nvml.dll`, `amdadlx64.dll`, `ControlLib.dll`) plus optional, separately installed PawnIO.
- Nothing leaves the PC except the update check against GitHub Releases. No analytics, accounts or crash upload.
- No code signing. README explains the SmartScreen "unknown publisher" prompt.
- MIT license (already in repo). Third-party notices file lists LHM (MPL-2.0), PresentMon (MIT), ADLX SDK (MIT), Vortice (MIT), Velopack (MIT), fonts (OFL).
- Overlay never injects into or hooks game processes.
- Opening Redline never applies anything. Slider changes are staged until Apply.
- Keep-or-revert countdown after Apply: **15 seconds**; no confirmation reverts.
- Start with Windows: off by default; only a stability-tested profile; applies **~15 s** after login.
- Auto-tune never raises power limit above 100% unless the user opted in. Cards with the 16-pin connector show a one-time warning before power > 100%.
- Sliders default to the Redline safe range; full driver range only behind "Advanced" with a warning.
- Auto-tune final result backs off from the highest passing step.
- Temperature guard default ceiling **83 °C** (user range 70–90 °C); cannot be disabled while a tune is applied.
- Efficiency mode keeps performance within **2%** of stock.
- Telemetry polling **1 s**; **5 s** while the UI is minimized/closed.
- Default profiles: **Send it** (max performance), **Whisper** (cool and quiet), **Factory** (stock, cannot be deleted).
- Themes: **Daylight, Midnight, Ember, Glacier, Neon** (exact palettes in Task 26). All text ≥ 4.5:1 contrast in every theme.
- Fonts: Space Grotesk (numbers/headings), Inter (text), bundled.
- The helper service and anything it executes live only in an admin-protected folder (`%ProgramFiles%\Redline\Helper\`). The SYSTEM service must never run code from a user-writable path (the Velopack app folder in `%LocalAppData%` is user-writable). A helper version change therefore needs one admin prompt; app-only updates need none.
- Git: Claude commits and pushes to `main` directly; CI runs on every push. Anthony never runs git steps.
- Verification: `dotnet test` locally when api.nuget.org is reachable from the workspace; otherwise push and read the CI run (`gh api repos/larosa023/redline/actions/runs?per_page=1`). Windows-only projects are verified only in CI.

## Review Focus

1. **Multi-GPU with a locked/integrated GPU** (e.g. laptop iGPU + dGPU, or iGPU with no tuning): app must list both, show only supported controls per device, and never fail discovery because one backend throws. → tests in Task 2 (`Discovery_OneBackendThrows_OthersStillListed`) and Task 20.
2. **Driver silently refuses or alters a value**: Apply must read back and surface the actual value, and auto-tune must treat a mismatch as "unsupported", not "stable". → Task 2 (`Apply_DriverClampsValue_ActualReported`), Task 10 (`Mismatch_StopsWalk_NotCountedAsPass`).
3. **GPU vanishes mid-session** (driver reset, TDR, eGPU unplug): telemetry returns nothing; guard/engine must not crash and must reapply Factory or last-good once the device returns. → Task 19 (`DeviceLost_EngineRecovers`).
4. **Corrupt or old-version settings/profile files**: load must fall back to defaults and keep a `.corrupt` backup, never crash at startup. → Task 4 (`Load_CorruptJson_BacksUpAndUsesDefaults`).
5. **UI open while helper is missing/stopped/old version**: UI shows a clear "Redline Helper isn't running" state with a repair button, never hangs on the pipe. → Task 19 (`Client_NoServer_TimesOutWithin2s`), Task 25.

```csharp
  int CoreStepMhz = 15, int MemStepMhz = 50, int CoreMarginSteps = 2, int MemMarginSteps = 1,

```
Performance algorithm: baseline at Factory (fail → `FailedAtBaseline`, device reset). Walk CoreOffset up by `CoreStepMhz` within `SafetyPolicy.SafeRange` (non-Advanced) until a step fails or range ends; a step passes iff `Completed && Errors==0 && !DriverReset && ApplyResult.Matches`. Core result = last pass − `CoreMarginSteps`×step (≥0). Then MemoryOffset the same with core fixed. PowerLimit untouched unless `AllowPowerAbove100`. Final run at result for `FinalDuration`; on fail back off one more step on each walked control and retry, max 2 retries, else Best = Factory. Every apply: `journal.MarkPending` before, `MarkConfirmed` after pass. Cancellation: apply last confirmed-good, Outcome `Cancelled`.
